# TC-FLOW-AUTH-001：普通账号权限与登录流程

| TestCaseId | 依据 | 场景 | 预期 |
|---|---|---|---|
| TC-FLOW-AUTH-001 | FL-AUTH-01 / SM-USER-07-006 | SA 创建普通账号、角色并关联后登录 | 普通账号可登录；侧边栏与角色授权一致 |
| TC-FLOW-AUTH-002 | FL-AUTH-03 / SM-USER-05-008 | 管理员禁用在线普通账号 | 当前会话不立即失效；退出后再次登录被拒绝 |
| TC-FLOW-AUTH-003 | FL-AUTH-03 / SM-USER-05-004 | 验证启用状态普通账号可再次登录（独立执行） | 账号处于启用状态时可登录 |
| TC-FLOW-AUTH-004 | FL-AUTH-03 / SM-USER-04 | 删除普通账号 | 删除后该账号登录被拒绝；管理员入口仍可用 |
| TC-FLOW-AUTH-005 | FL-AUTH-01 | 登录输入边界 | 空值、格式错误、特殊字符和长度边界按产品规则校验，不建立错误会话 |
| TC-FLOW-AUTH-006 | FL-AUTH-01 | 登录异常分支 | 错误密码、重复提交和请求失败均给出明确结果，不进入已登录页面 |
| TC-FLOW-AUTH-007 | FL-AUTH-02 | 普通账号权限查询 | 普通账号只能查询和访问角色授权范围内的功能，空/精确/模糊/无匹配查询行为符合页面规则 |
| TC-FLOW-AUTH-008 | FL-AUTH-01 | 普通账号创建异常 | 必填、格式、长度、重复属性、重复提交和保存失败均被正确处理，不产生脏数据 |
| TC-FLOW-AUTH-009 | FL-AUTH-02 | 在线权限变更生效时机 | 权限变更前后通过独立会话对照，刷新或重新登录后的菜单和受保护操作符合产品规则 |
| TC-FLOW-AUTH-010 | FL-AUTH-05 / FL-AUTH-07 | 多端并发与授权异常 | 在获批的双会话和授权环境中记录并发状态；缺少前置条件时标记 BLOCKED/MANUAL，不虚构 PASS |

## 公共前置与约束

- Web 前端：`http://192.168.12.195:8223/`
- 使用 SA 通过页面创建和清理本批次普通账号、角色及关联。
- 普通账号和角色使用运行时前缀，不使用生产/基线账号。
- 不修改产品源代码、AutomationId、测试钩子或真实产品文件。
- 密码只通过运行时环境变量传入，不写入 TestCase、代码或报告。
