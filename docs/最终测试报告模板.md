## 设计生成规则

- TestCase 模型：`MODULE → FEATURE → OPERATION → BUSINESS_RULE → SCENARIO → TESTCASE`。
- 原子用例只验证一个主要业务规则；不同根因必须拆分。
- 只有同一业务规则、同一步骤和同一预期逻辑允许参数化。
- 查询先建立 Query Matrix；新增、修改、删除先评估等价类、边界、决策表、状态矩阵、权限矩阵和 CRUD 生命周期。
- 明确边界才写具体值；未知 min/max 不得猜测，生成规则待确认项。
- 新细粒度用例必须生成新 TestCaseId，最近结果显示“尚未执行”，不得继承历史 PASS。
- 正式 Catalog 物化到项目 `test-cases/catalog/`；`outputs/` 仅保存生成过程产物。
- 生成正式报告前必须校验 Source Catalog、Materialized Catalog 和报告主 Catalog 的 TestCaseId 双向一致。
