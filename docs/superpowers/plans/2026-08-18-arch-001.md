# ARCH-001 As-Built Architecture Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 从 `src_m_rsscomposer` 与 `src_m_ui` 的当前真实源码生成带证据等级的 As-Built 设计基线，供后续人工审查和 `TEST-DESIGN-001` 使用。

**Architecture:** 采用只读源码扫描与人工校验相结合的方式，先建立可重复的源码树基线，再从解决方案/项目、Controller/API、前端路由/API、认证权限和配置中提取事实，最后生成 13 份中文 Markdown、一个机器可读 JSON 索引和覆盖统计。所有关系标记为 `CONFIRMED_FROM_CODE`、`CONFIRMED_FROM_RUNTIME`、`INFERRED` 或 `UNKNOWN`，不把推断写成事实。

**Tech Stack:** PowerShell/.NET UTF-8 只读扫描、Markdown、JSON、Mermaid；不执行 npm/dotnet restore/build，不启动前后端，不调用 API，不连接数据库。

## Global Constraints

- 只读取 `D:\HZ_RSS40\03_trunk\src_m_rsscomposer` 与 `D:\HZ_RSS40\03_trunk\src_m_ui`，不得修改、格式化、构建、还原或生成到真实源码目录。
- 只写入 `E:\automated-testing`，保留已有未提交修改，不执行 `git reset`、`git clean`、`git checkout -- .`。
- 本阶段禁止创建 `TC-*.md`、Playwright spec、API test、Unit test，禁止执行真实业务测试，禁止连接真实数据库，禁止生成 Word/操作手册。
- 文档使用中文，保留真实类名、方法名、路由、字段和 DTO 标识；禁止复制大段源码。
- 文档与 JSON 不得包含密码、Token、Secret、Cookie、Authorization Header、API Key、完整连接字符串或私人凭据路径。
- 生成前后使用同一排除规则计算前后端文件数和 SHA-256 源码树哈希，并要求一致。
- 完成 ARCH-001 后停止，等待人工审查，不自动进入 `TEST-DESIGN-001`、`TEST-RUN-001` 或 `DOC-001`。
