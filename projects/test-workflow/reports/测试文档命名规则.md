# 测试文档命名规则

## 1. 适用范围

适用于依据功能文档或流程文档生成的测试报告 Markdown 文件。

## 2. 命名格式

```text
测试依据原文件名（去掉 .md）_测试类型报告.md
```

测试类型只使用以下两种：

- 功能依据：`_功能测试报告.md`
- 流程依据：`_流程测试报告.md`

## 3. 示例

| 测试依据 | 输出文档 |
|---|---|
| `功能_02_Web管理端_系统管理(4).md` | `功能_02_Web管理端_系统管理(4)_功能测试报告.md` |
| `流程_01_权限与登录(3).md` | `流程_01_权限与登录(3)_流程测试报告.md` |

## 4. 图片证据规则

- 图片证据不单独作为报告模块；在测试结果列表右侧新增 `图片示例` 列，与对应行为同一行展示。
- 列顺序固定为：`用例/流程` → `TestCaseId` → `结果` → `实际验证` → `图片示例`。
- `图片示例` 使用缩略图，点击缩略图打开原图；多个行为截图在同一个单元格内按顺序排列。
- 图片可使用 Markdown 或 HTML 图片语法嵌入，并同时提供原图链接。
- 图片路径使用相对于报告文件的仓库路径，不使用本机绝对路径。
- 图片文件名使用 `测试类型-TestCaseId-场景说明.png`，例如 `功能-TC-SM-USER-002-新增用户.png`。
- PASS、ERROR 和 BLOCKED 均尽量保留对应截图；没有截图时必须紧跟用例说明原因，不得用文字冒充图片证据。
- SKIPPED 用例不生成截图，并在流程状态中说明未执行原因。
