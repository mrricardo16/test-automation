# 测试文档命名规则

## 1. 适用范围

适用于依据功能文档或流程文档生成的测试报告 Markdown 文件。

## 2. 命名格式

```text
测试依据原文件名（去掉 .md 和末尾括号编号）_报告类型.md
```

测试类型只使用以下四种：

- 完整测试用例报告：`_完整测试用例报告.md`
- 问题反馈报告：`_问题反馈报告.md`

## 3. 示例

| 测试依据 | 输出文档 |
|---|---|
| `功能_02_Web管理端_系统管理(4).md` | `功能_02_Web管理端_系统管理_完整测试用例报告.md`、`功能_02_Web管理端_系统管理_问题反馈报告.md` |
| `流程_01_权限与登录(3).md` | `流程_01_权限与登录_完整测试用例报告.md`、`流程_01_权限与登录_问题反馈报告.md` |

## 4. 图片证据规则

- 图片证据不单独作为报告模块；在测试结果列表右侧新增 `图片示例` 列，与对应行为同一行展示。
- 完整测试用例报告列顺序固定为：`用例/流程` → `TestCaseId` → `状态` → `实际验证` → `图片示例`。
- 问题反馈报告列顺序固定为：`问题/场景` → `TestCaseId` → `状态` → `分类` → `严重程度` → `预期` → `实际` → `证据` → `图片示例`。
- `图片示例` 使用缩略图，点击缩略图打开原图；多个行为截图在同一个单元格内按顺序排列。
- 图片可使用 Markdown 或 HTML 图片语法嵌入，并同时提供原图链接。
- 图片路径使用相对于报告文件的仓库路径，不使用本机绝对路径。
- 图片文件名使用 `测试类型-TestCaseId-场景说明.png`，例如 `功能-TC-SM-USER-002-新增用户.png`。
- 每条用例或问题在右侧 `图片示例` 列提供报告目录内的相对图片链接；图片可为该场景、同模块或同流程的可复审示例，并在实际验证/实际中说明边界。
- 不建立独立的图片复审章节。不得使用本机绝对路径、`..` 路径或远程图片地址。

## 5. 状态与问题收集规则

- 状态只使用：`PASS`、`FAIL`、`ERROR`、`BLOCKED`、`MANUAL`、`SKIPPED`。
- 完整测试用例报告必须覆盖查询空/精确/模糊/无匹配/空格/特殊字符/非法字符/长度/分页/重置，以及新增必填/格式/边界/重复属性/重复提交/保存失败/保存后查询、修改、删除、权限、状态恢复和流程跨步骤场景；未真实执行时记录 `SKIPPED` 或 `MANUAL`，不得虚构 PASS。
- 问题反馈报告只收集 `FAIL`、`ERROR`、`BLOCKED`、`MANUAL` 和具有开发或环境反馈价值的 `SKIPPED`，并保留 TestCaseId、预期、实际、分类、严重程度、证据和图片示例。
