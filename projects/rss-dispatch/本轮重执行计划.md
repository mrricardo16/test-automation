# RSS调度 Web 系统管理与权限登录重执行计划

**目标：** 依据 `功能_02_Web管理端_系统管理(1).md` 与 `流程_01_权限与登录.md`，重新执行系统管理页面核验和权限登录链路，并把 UI、网络、数据库/Redis/日志证据分开记录。

**本轮不自动执行：** 桌面端并发（`FL-AUTH-05`）、改名/篡改 `rss.lic`、修改系统时间、清空 Redis。这些动作会改变机器或共享服务状态，需单独授权和可验证的复位方案。

## 执行边界

- 管理员操作账号必须是普通管理员；`sa` 只做特判对照，不用于证明普通角色权限。
- 被测账号、角色、菜单使用本批次专用前缀，完成后按文档顺序清理。
- 管理员与被测账号使用两个独立浏览器窗口/标签页上下文。
- 保存与删除均记录原始 UI 文案，并在可用时采集网络响应中的 `statusCode` 与 `isSuccess`。
- 任何清理动作必须避开现有 `sa`、内置角色、系统菜单、系统字典和正在使用的外部系统配置。
- 所有产物写入 `E:/automated-testing/RSS调度`。

## 结果分类

只使用 `PASS`、`FAIL`、`ERROR`、`BLOCKED`、`MANUAL`、`SKIPPED`。若缺少普通管理员账号、双浏览器、数据库/Redis/日志观测权限或安全复位条件，对应流程标记 `BLOCKED`，不把环境缺失算成产品 `FAIL`。
